# ADR 0006 - ULID Identifiers

## Status

Accepted.

## Context

Cordell needs application-generated identifiers for personnel, assets, and custody transactions.

The identifiers should be easy to store, easy to log, reasonably readable, and suitable for distributed generation without relying on database sequences for domain entities.

## Decision

Cordell will use ULIDs as application-generated identifiers.

ULIDs will be stored as text in PostgreSQL.

## Consequences

### Positive

- IDs are generated by the application.
- IDs are lexicographically sortable by timestamp.
- IDs are shorter than canonical UUID strings.
- IDs are URL-safe and log-friendly.
- The current string-based domain identifier types remain valid.

### Negative

- ULIDs expose approximate creation time.
- Ordering is not guaranteed within the same millisecond unless monotonic generation is used.
- PostgreSQL cannot use its native UUID type for these IDs.

## Alternatives Considered

### UUID

UUIDs are widely supported and PostgreSQL has a native UUID type, but canonical UUID strings are longer and not naturally time-sortable unless using newer timestamp-oriented variants.

### Database sequences

Database sequences are simple, but they make IDs database-centered and more predictable.

### UUIDv7

UUIDv7 is time-ordered and increasingly relevant, but ULID is more readable and fits Cordell's current string-based ID model.
